# v0.5 封面加载修复

1. 抖音保留 cover 的全部有效地址以及 origin_cover、raw_cover、dynamic_cover，静态封面优先；快手保留 coverUrls 的多个 CDN 地址及缩略图备用地址。去掉空地址及重复地址。
2. 读取封面时附带来源页、常规浏览器 User-Agent 和图片 Accept 请求头，不向图片域名转发视频解析的 Cookie。
3. HTTP 失败、超时、图片解码失败或返回空图片时自动切换备用地址。每个地址的连接、跳转和读取共享 4 秒预算；一轮请求共享 12 秒预算，最多尝试 8 个地址。系统 DNS 等底层操作可能超出套接字计时范围。
4. 封面与视频解析使用独立执行线程。重新解析或退出时取消过期任务，旧封面结果不会覆盖新视频。
5. 失败提示可点击重试；在封面请求进行中禁用重复点击。
6. 加载上限由 3 MiB 提升至 8 MiB，仍先检查图片尺寸，再缩小到最长边不超过 1600 像素显示。

本次针对图一的封面问题，不调整用户已确认的页面顺序和四宫格。图二为误上传。视频下载流程没有修改。

## 故障证据与验证范围

旧加载代码在回归测试中无法处理首图 403、慢响应、解码失败及 3 MiB 以上封面；新增两项解析测试也复现了抖音只有 origin_cover 和快手首个封面地址为空时丢失有效封面。

用户的抖音短链在当前电脑网络返回普通 JPEG，本次未复现手机的偶发失败，不能把某个请求头或图片格式认定为那次失败的确切原因。修复着重处理已证实缺失的备用地址及超时恢复路径。APK 和真机验证范围见 verification.md。
