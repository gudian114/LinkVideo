# 视频链接解析 · v0.4

## 目标与假设
原生 Android Java 应用，Android 8.0 / API 26 起。用户粘贴一段含单个公开视频链接的分享文案，自动解析平台、标题、作者、封面和媒体地址，并将可用结果保存为 MP4。

手机独立运行作为默认方案，无服务器、第三方解析服务、账号或 Cookie 导入。平台要求登录、验证、付费或无法提供媒体时显示明确原因，不将识别链接当作解析成功。抖音、快手、B站的网页/API均可能变化，首版属于公开链接解析实验实现。

## 方案取舍
- 原生 Java：直接调用 Android API，解析核心可在 JVM 测试，无跨语言运行时，适合当前 Android 单平台需求。选用此方案。
- Kotlin：同样可行，但当前功能无需增加 Kotlin 构建依赖。
- Android + 服务器：后期便于集中维护解析规则，但增加部署、运维和数据传输；当前不引入。

## 数据流
分享文案 → 提取 HTTPS 链接 → 校验平台域名 → 有限次短链展开 → 平台解析 → VideoResult → 下载计划 → MP4。

- LinkInput：从中文文案提取链接；检查精确域名及子域名边界；支持 B站 BV/av 标识；拒绝多条支持平台链接，避免默默选错。
- HttpFetcher：HTTPS、连接/读取超时、重定向次数和响应体上限；每一步跳转保持在相应平台域名内。
- VideoParser：B站视频元信息/播放地址；抖音和快手公开页的嵌入 JSON。抖音按 `aweme_id` 匹配，并在分享页无作品数据时使用页面 Cookie 或匿名 `ttwid` 请求作品详情；快手兼容 Apollo 和当前 `INIT_STATE` 并按分享作品 ID 绑定，避免误取推荐项。
- VideoResult / MediaStream：保存来源、元信息、媒体类型及必要请求头；分离音视频、分段、播放清单不冒充单个完整 MP4。
- DownloadPlan / VideoDownloader：完整 MP4 直接下载；B站优先选择 H.264 与 AAC DASH 轨道，携带来源请求头下载后用 Android MediaMuxer 无损封装。
- MainActivity：中文页面，粘贴后延迟解析；新输入使旧结果失效；后台网络操作；受保护地址不允许直接复制；下载保存到“下载/拾链”。

## 后续框架
后续按真机反馈增加长任务通知、暂停/恢复、失败重试、分段合并、更多编码兼容和解析规则更新。

## 验证边界
离线夹具测试覆盖链接提取、平台校验、媒体字段及错误结果；在线探测单独记录时间和结果，不把夹具测试等同于平台当前可用性。使用 Gradle 构建 Debug APK；没有真机/模拟器时明确记录界面与安装尚未验证。
