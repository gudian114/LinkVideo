# v0.17：手机解析诊断与批量输入调整

## 已确认需求

- 用户手机 v0.16 抖音视频仍失败，其他平台正常。本机成功不足以确认手机修复。
- 用户暂不连接 USB，明确选择先提供“可查看错误详情”的版本。
- 非空退格正常删字；输入已为空时再次退格删除当前框，后续框更新编号；至少保留一框。
- 一键清空恢复为一个空框；保留换行开框、空白换行提示、最多十框及重复链接确认。
- 暂不实现无效链接检测/统计；不上传 GitHub。

## 实现

每次 parse 使用独立的网络诊断包装器，保留普通错误被备用流程捕获后的类型信息。记录 HTTP 状态、耗时、字符数、Content-Type/Encoding 分类、服务器与设备时间差、ttwid 是否存在、返回结构中是否有作品数据。不复制请求 URL、query、响应正文、Cookie 值或异常 message，诊断不自动发送。

主页/批量解析失败时显示“查看错误详情”，弹出可滚动、可选中文字，提供“复制错误详情”。取消解析仍传播取消异常，不将其包装成解析失败；每次请求不共享诊断事件。

BatchState 删除空 Entry、重置整批。BatchActivity 重排原 Row 索引及标签，使用动态索引写回输入、解析和下载。已移除或已重置的 Row 回调失效；忙碌时不允许删框。

BatchLinkInput 在退格发生前检查是否已为空，兼容 DEL、deleteSurroundingText、deleteSurroundingTextInCodePoints。有文字时交给系统正常编辑；删除最后一个字符不会在同一次调用中删框。单次已排队删除有保护。

## 当前证据与限制

本机对用户两条短链再次取得视频结果。实际诊断显示分享页只有路由信息、旧版详情有 status_code=11110，后续普通详情仍可能返回作品；其中一条经过匿名注册及回调。因此 HTTP 200 不等于取得作品数据，也不能据相同提示认定手机是同一原因。

本版保留现有网络请求和解析策略，增加可定位依据，没有在缺少手机响应的情况下宣称修复抖音。尚未验证 Android 软键盘事件、安装和手机网络；下一步需要手机失败后复制的诊断内容。
