# v0.18：抖音 403 后备读取

## 本次证据

用户提供两份 v0.17 Android 15 报告，主页和批量共用的解析流程在普通详情、匿名会话后的普通详情、签名详情均收到 HTTP 403。分享页只有路由数据；旧接口返回 status_code=11110。匿名注册及回调成功，时间差 0–1 秒。因此修复针对详情读取阶段，不修改输入框或批量设置。

与 v0.12/v0.13 对比，DouyinRequestSignature 内容一致，第一次普通详情 URL/请求头一致。无法仅由版本先后确定平台返回 403 的原因，也不以简单降级代替修复。

## 实现

- HttpClient 默认不支持网页读取；AndroidHttpClient 保留 HttpFetcher 请求，仅为 Android 入口提供 WebView 后备读取。
- 仅在原有步骤未取得作品数据时启用，加载 HTTPS www.douyin.com 上对应 video/note 页面；从相同来源获取该作品详情。
- DouyinBrowserPage 限定入口路径、作品编号和请求参数；响应须 status_code=0 且 aweme_id 与目标相同，避免取到推荐作品。
- 后备成功后沿用已有 VideoResult / ImagePostResult 生成流程，把来源页、UA 和匿名 Cookie 交给媒体请求。
- WebView 在主线程创建并销毁；后台等待最多 45 秒，每次失败响应后间隔 8 秒，最多 4 次；取消、Activity 退出、渲染进程退出会清理组件。
- 顶层只允许 HTTPS www.douyin.com，无用户信息、无非标准端口；禁止文件/内容访问、地理位置、混合内容、权限授予。无 JavaScript 原生桥接。主框架请求、导航和轮询均检查来源。
- ParseDiagnostics 记录“网页内核”状态，保留失败详情入口，不写出 Cookie 值、完整 URL、响应正文、签名或文案。

## 验证与限制

151 项独立核心测试通过，覆盖全部原生详情 403 后恢复、错误作品拒绝、失败诊断、取消传播、官方来源与作品参数检查。Android 编译、资源处理、lint 与 APK 构建通过。

用户两条链接对应作品 7685159514829025465 与 7686402981592741989。全新电脑 Chrome 会话使用生产脚本及相同桌面 UA 均读取到匹配作品；真实响应回放到生产解析器得到 1 路视频、3 个封面地址，时长分别 160.334 秒、109.552 秒。

没有连接 Android 手机或模拟器。Chrome 结果不能证明 WebView 上的网页兼容性、平台校验结果与媒体下载表现。仍需验证主页/批量、加载时退出/旋转、45 秒超时、重定向与连续解析；如失败，使用新诊断报告继续定位。
