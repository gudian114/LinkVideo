# v0.19 抖音网页等待修复

## 已确认的问题

用户 1234.txt 显示：v0.18 / Android 15，原生详情仍 403，网页阶段 45021ms 后 SocketTimeoutException。用户回退 v0.12/v0.13 也失败。本次是新链接，截至打包前尚未收到该链接；不能据此断言抖音修改了哪项防抓规则。

v0.18 代码只在 onPageFinished 后开始轮询，主框架网络、HTTP、TLS 失败没有分别处理；网页 fetch 的 pending 没有自己的截止时间。报告也没有记录网页开始、完成和脚本回调，因此不能确认用户手机具体落入了哪条等待路径。

## 修改

- 在 loadUrl 后启动独立轮询，不再等整页加载完成。优先捕获官方作品页自身 fetch / XMLHttpRequest 的详情响应；来源路径与 aweme_id 必须匹配，只接受 status_code=0 的目标作品。
- 保留最多 2 次主动读取，每次截止时间 6 秒。主动请求与网页观察器分离，超时后的晚到响应不能覆盖新结果。
- 网页阶段显示官方作品页面、等待秒数与“取消本条解析”。平台如要求验证，由用户在官方页面操作；不会代做验证。成功后自动关闭并返回原结果界面。
- 正常会话总预算 25 秒；主线程/组件无响应时后台等待上限 30 秒。主框架网络和 HTTP 错误及时结束，TLS 错误取消连接。错误不再被最终通用提示覆盖。
- 诊断记录系统网页组件版本、启动/可见/完成次数、文档状态、轮询/回调数、详情请求与 HTTP 状态、网络/证书错误码及脚本错误数量。仅数值/枚举，无 URL、网页正文、Cookie 值、脚本消息或用户文案。
- 顶层仍限制 HTTPS www.douyin.com，子框架仅允许 HTTPS 导航，以支持官方页面的验证内容。无 JavaScript 原生桥接，禁止文件、内容、混合内容和额外权限。

## 验证

- Node 测试执行由生产 Java 类导出的脚本：请求永久挂起、加载期间捕获、XHR 与错误 ID 拒绝、晚到 HTTP200 同 ID 响应、无关正文不泄漏。旧脚本 5 项失败；最终 5 项通过。晚到 HTTP200 覆盖问题由复查发现，强化用例先失败后修复。
- 新的诊断回归：移除网页状态保留时 152 项中 1 项失败；恢复后全部通过。
- 浏览器模拟 412×820 手机窗口，故意悬挂图片请求：没有触发 page load 完成事件，仍通过 page-xhr 取得作品 7685159514829025465。这证明修复不依赖页面完全加载；不等于证明手机原故障就来自图片。
- 最终脚本对先前第二条链接对应作品 7686402981592741989 取得匹配数据，来源 direct。
- 无 Android 真机或模拟器；官方网页验证交互、手机网络策略和实际下载表现仍未验证。需用户覆盖安装后复测本次新链接。

## 参考

Android 官方 [WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient) 文档区分页面加载完成、页面内容可见、网络/HTTP/TLS 错误回调。本次根据这些不同阶段处理失败，不把 onPageFinished 当成唯一读取入口。
