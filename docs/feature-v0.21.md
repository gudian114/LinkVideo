# v0.21 公告与抖音网页自动显示

## 使用行为

- 启动主页默认显示“公告”，正文为：如果解析时出现长时间未响应，请自行在设置打开“显示抖音解析网页”拉起网页后认证。
- 正文下依次为蓝色“关闭”按钮和“不再提示”复选框。点击关闭时保存勾选状态；勾选后下次启动不再显示。
- 设置页头部最右边的喇叭图标可随时打开公告，不受“不再提示”影响。在此取消勾选并关闭可恢复开屏提示。
- 旋转屏幕时恢复公告是否打开及尚未提交的勾选状态；Activity 销毁时关闭其窗口，避免遗留窗口。
- “显示抖音解析网页”仍默认 OFF。原生解析成功时不加载网页；只有抖音网页后备阶段才启动自动显示判断。主页和批量共用。
- 页面加载进度增加或文档从 loading 推进到 interactive/complete 时重置停滞计时；重复回调、同一进度、页面重载导致的进度回退不延后弹出。
- 连续约 8 秒无上述进展，或隐藏读取累计约 16 秒仍未取得作品时，尝试显示。轮询间隔 750 毫秒，因此实际触发可能稍晚；不依赖主页的固定 88%，也不把重复请求次数视为进展。
- 只在当前 Activity 存活且窗口有焦点时显示；后台、其他页面或其他弹窗占据焦点时不抢窗口。超时/结束/取消后不再弹出。
- 将已加载的同一个 WebView 移入官方网页对话框，恢复透明度、触摸、键盘和无障碍焦点，不重新加载页面，不改写开关。
- 显示后预留 60 秒，用户可处理官方页面认证或取消本条。未显示时会话上限 25 秒；主线程异常时外层等待上限 90 秒。成功后立即关闭，取消/离开销毁 Activity 后移除回调和网页。
- 延迟的 JS 回调使用统一会话期限，避免原先 6 秒回调超时抢在自动显示之前结束解析。

## 稳定性依据与边界

使用 Android [SystemClock.elapsedRealtime](https://developer.android.com/reference/android/os/SystemClock) 计算时间间隔，避免用户修改系统时间影响计时。窗口判断使用 [Activity.hasWindowFocus](https://developer.android.com/reference/android/app/Activity#hasWindowFocus())，有别于仅判断 Activity 对象存在。

解析百分比表示步骤而非真实下载比例，不适合单独判断需要认证。这里以网页加载进展和有界等待作折中；慢网络也可能触发显示，但不重复发起加载。

这些机制不能保证所有 Android 厂商、系统 WebView 版本和平台挑战均可用。当前没有连接真机，仍需验证输入认证、返回/切后台、旋转及慢网络。保留手动开关和错误详情入口。认证须用户自行完成。

## 验证范围

新增独立 Java 状态测试覆盖计时边界、任意进度值、进度回退、连续慢进展、后台窗口、结束与显示后期限；复用解析器与网页脚本测试。编译/lint/签名/归档记录见同版 verification.md，不把离线测试称作手机实测。
